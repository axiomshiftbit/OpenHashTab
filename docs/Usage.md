# Сравнение файлов, отчёты и командная строка

## Настройки алгоритмов и прогресс

В настройках доступен поиск по имени без учёта регистра. Фильтр изменяет только видимый список: флажки скрытых алгоритмов сохраняются. Выбор строки показывает длину результата и параметры алгоритма.

Наборы применяются ко всему списку, включая скрытые строки:

- «Рекомендуемые»: SHA-256 и BLAKE3.
- «Совместимость»: MD5, SHA-1, SHA-256 и SHA-512. MD5 и SHA-1 нужны для старых контрольных сумм и не рекомендуются для защиты от подмены.
- «Все» / «Ни одного»: включить / выключить все алгоритмы.
- «Свои настройки»: состояние после ручного изменения флажков.

Изменения сохраняются для следующих вычислений. В уже вычисленном окне набор результатов не пересчитывается автоматически.

Под основными кнопками показывается обработанный объём, общий объём и средняя скорость с начала операции. Оценка оставшегося времени появляется после накопления данных, может колебаться и исчезает после завершения или отмены. Объём измеряет чтение файлов, а не сумму работы каждого алгоритма: включение нескольких алгоритмов не умножает число байтов файла. Единицы KiB/MiB/GiB означают степени 1024.

## Сравнение двух файлов или папок

1. Нажмите «Сравнить…» в основном окне.
2. Укажите левый и правый пути вручную либо выберите их кнопками «Файл…» / «Папка…».
3. Выберите алгоритм; по умолчанию SHA-256.
4. Нажмите «Сравнить». Во время работы доступна отмена.
5. Посмотрите таблицу результатов и счётчики; сохраните CSV или JSON соответствующей кнопкой.

Для двух файлов сравниваются их данные независимо от имени. Для папок элементы сопоставляются по относительному пути без учёта регистра, по правилам Windows ordinal comparison. Пустые каталоги также участвуют. Даты, ACL, атрибуты, альтернативные потоки NTFS и содержимое архивов отдельно не сравниваются. Результат хеширования относится к основному потоку данных файла.

В столбце ожидаемого хеша находится результат левой стороны, в столбце вычисленного — правой. Для каталогов и несовпадения типов «файл/папка» хеши пустые. Строка `./` описывает корень сравнения; пути каталогов заканчиваются `/`.

Символические ссылки на файлы читаются как целевые файлы. Ссылки и точки повторного анализа каталогов не обходятся и отображаются как ошибки, чтобы исключить циклы и незаметный выход за пределы дерева. Неоднозначные имена, отличающиеся только регистром в регистрозависимом каталоге NTFS, также вызывают ошибку. Удалённые и недоступные корни являются ошибками чтения; отсутствующие элементы внутри двух доступных деревьев отмечаются отдельно.

Пакетные операции запрещают запись и удаление открытого для чтения файла. Уже работающий несовместимый писатель, изменение размера/времени модификации между обходом и чтением, отказ доступа и ошибка чтения дают ошибку вместо частичного хеша. Сравнение не создаёт снимок всей файловой системы: изменения других элементов дерева между его обходом и чтением возможны. Для изменяемых наборов данных используйте стабильную копию.

## Отчёт текущей проверки

После вычисления нажмите «Отчёт проверки…» и выберите JSON или CSV. Отчёт содержит все рассчитанные алгоритмы, а не только выделенные строки. Если поле «Проверить совпадение» заполнено распознанным хешем, оно становится ожидаемым значением для результатов соответствующей длины. Иначе используются контрольные суммы исходного файла проверки или соседнего checksum-файла.

Когда расширение файла однозначно задаёт алгоритм, ожидаемое значение применяется к этому алгоритму. Для неизвестного формата сумма сопоставляется с включёнными алгоритмами той же длины; это может дать несколько строк, включая несовпадения других алгоритмов. Одинаковая длина не означает одинаковый алгоритм. Если одному файлу соответствует несколько ожидаемых сумм, каждая отражается отдельно. При ошибке чтения вычисленный хеш остаётся пустым; известная ожидаемая сумма сохраняется.

CSV/JSON — форматы отчёта. Для последующего открытия программой файла контрольных сумм используйте обычную кнопку «Экспорт в хеш-файл»; JSON/CSV не являются входным форматом команды `verify`.

## Командная строка

`OpenHashTabCLI.exe` устанавливается рядом с `StandaloneStub.exe`. Установщик не изменяет `PATH`. Пример PowerShell для установки на весь компьютер:

```powershell
$cli = 'C:\Program Files\OpenHashTab\OpenHashTabCLI.exe'
& $cli --version
& $cli --help
& $cli algorithms
& $cli hash 'C:\Data\file.bin'
& $cli hash --algorithm SHA-512 'C:\Data\file.bin' 'C:\Data\another.bin'
& $cli hash --algorithm SHA-512/256 'C:\Data\folder'
& $cli compare 'C:\Data\before' 'C:\Data\after'
& $cli compare --algorithm Kupyna-256 'C:\Data\first.iso' 'C:\Data\second.iso'
& $cli verify --algorithm SHA-256 'C:\Data\checks.sha256'
& $cli verify --algorithm Whirlpool 'C:\Data\checks.whirlpool'
& $cli hash --progress --format csv 'C:\Data\large.iso'
& $cli hash -- '-starts-with-dash.bin'
```

Для установки только текущему пользователю путь может отличаться; используйте фактический каталог установки.

| Параметр | Значение |
|---|---|
| `--algorithm NAME` | Имя из `algorithms`, без учёта регистра. По умолчанию SHA-256. Пробелы в имени требуют кавычек, например `"GOST 2012 (256)"` |
| `--format json` | JSON в stdout; значение по умолчанию |
| `--format csv` | CSV в stdout |
| `--progress` | Обработанные/общие байты в stderr, не чаще двух раз в секунду; stdout остаётся машинным отчётом |
| `--` | Заканчивает разбор параметров, все следующие аргументы — пути |
| `--help` | Справка |
| `--version` | Версия; применяется вместо команды |

`hash` вычисляет буквальное содержимое файлов, включая checksum-файлы; папки обходятся рекурсивно. `verify` принимает один файл с именованными контрольными суммами GNU (hex/base64) либо SFV. Алгоритм выбирается явно: расширение в CLI не переопределяет SHA-256 по умолчанию. Для SFV укажите `--algorithm CRC32`. Имена в checksum-файле должны быть относительными, без `..`; они разрешаются относительно каталога самого checksum-файла. Пустой, нераспознанный файл, некорректный UTF-8, абсолютный путь или неподходящая длина суммы приводят к ошибке. Это не изолированная среда: допустимая ссылка на файл может указывать за пределы каталога.

Настройки алгоритмов GUI не меняют алгоритм CLI. Ctrl+C или Ctrl+Break отменяет текущую операцию. Частичный хеш отменённого файла не публикуется; уже готовые строки остаются в отчёте.

### Сохранение отчётов и обработка результата

В `cmd.exe` перенаправление сохраняет исходный UTF-8 вывод программы:

```bat
"C:\Program Files\OpenHashTab\OpenHashTabCLI.exe" compare --format json "C:\Data\before" "C:\Data\after" > comparison.json
set "result=%ERRORLEVEL%"
echo Exit code: %result%
```

В PowerShell код нужно сохранить сразу после вызова. Windows PowerShell 5.1 при обычном `>` записывает текст в UTF-16LE; для JSON, предназначенного другим программам, явно выберите UTF-8:

```powershell
$savedEncoding = [Console]::OutputEncoding
try {
    [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
    $report = & $cli compare 'C:\Data\before' 'C:\Data\after'
    $code = $LASTEXITCODE
} finally { [Console]::OutputEncoding = $savedEncoding }
[IO.File]::WriteAllText('C:\Data\comparison.json', ($report -join "`n"), [Text.UTF8Encoding]::new($false))
switch ($code) {
    0 { 'Совпадает' }
    1 { 'Есть различия или отсутствующие элементы' }
    2 { throw 'Неверные аргументы' }
    3 { throw 'Ошибка чтения, операции или записи отчёта' }
    4 { 'Отменено пользователем' }
    default { throw "Неожиданный код: $code" }
}
```

Сохраняйте отчёт вне сравниваемых деревьев, чтобы он сам не попал в набор входных файлов. Ненулевой код не исключает наличия полезных строк в stdout: проверяйте и код, и `status` каждой строки.

| Код | Смысл |
|---:|---|
| 0 | Все запрошенные операции завершились успешно; сравниваемые элементы совпали |
| 1 | Есть несовпадение или элемент, отсутствующий с одной стороны сравнения |
| 2 | Ошибка аргументов |
| 3 | Ошибка чтения, операции или записи stdout |
| 4 | Отмена |

При смешанных результатах отмена имеет приоритет над ошибкой чтения, ошибка — над различиями. Ошибка вывода отчёта всегда возвращает 3.

## Формат отчёта

JSON имеет версию схемы и массив строк:

```json
{
  "schema_version": 1,
  "results": [
    {
      "path": "file.bin",
      "algorithm": "SHA-256",
      "expected": "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad",
      "actual": "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad",
      "status": "match",
      "error": ""
    }
  ]
}
```

CSV использует эти же шесть полей в порядке `path,algorithm,expected,actual,status,error`. Разделитель — запятая, строки CRLF, все поля заключены в двойные кавычки, вложенные кавычки удваиваются. Хеши записываются строчными шестнадцатеричными символами без зависимости от настроек GUI.

Статусы: `computed`, `match`, `mismatch`, `missing_left`, `missing_right`, `error`, `cancelled`. Отсутствующие значения — пустые строки. Ошибки Win32 содержат числовой код и текст на языке Windows; для автоматической обработки используйте статус и код возврата, а не локализованный текст.

JSON сохраняет имена точно. В CSV перед полями, которые могут интерпретироваться таблицей как формулы (`=`, `+`, `-`, `@`, в том числе после пробелов; либо начальные TAB/CR/LF), добавляется апостроф. Для точного машинного переноса таких имён используйте JSON.
