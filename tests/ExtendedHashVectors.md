# Эталонные данные дополнительных алгоритмов

`ExtendedHashVectors.h` содержит 6 998 примеров с явно записанными входными
байтами, 12 примеров RFC 9861 для больших сообщений и 28 граничных примеров.
Ожидаемые результаты
получены из перечисленных ниже опубликованных наборов либо независимых
реализаций. Производственный код OpenHashTab для их генерации не используется.

`CoreTests` проверяет обычные примеры порциями по 1, 7, 31, 127 и 8192 байта,
большие — по 127, 8192, 8193 байта и одним вызовом. Пустые обновления допустимы.
До и после выходного буфера стоят контрольные области по 16 байтов.

`ExtendedHashTests` дополнительно проверяет те же эталоны с намеренно
невыровненными адресами входа и выхода. На Linux этот тест собирается с
AddressSanitizer/UndefinedBehaviorSanitizer; на Windows — для x86/x64/ARM64.
Локальная сборка на Linux: `cmake -S tests/portable -B build/portable`,
`cmake --build build/portable`, `ctest --test-dir build/portable --output-on-failure`.
Требуется загруженный подмодуль XKCP.

Отдельная регрессия Kupyna-256/512 передаёт `512 МиБ + 17 байтов` одним
обновлением и порциями по 1 МиБ, проверяет одинаковый результат и счётчик
длины свыше `2^32` битов. Также проверяется перенос из младших 64 битов
счётчика в старшие 32 бита. Это проверка потоковой обработки и арифметики,
а не дополнительный независимый криптографический эталон. Пиковая память
этого теста — около 512 МиБ без учёта накладных расходов санитайзера.

| Варианты | Примеров на вариант | Источник и выбор данных |
|---|---:|---|
| Groestl-224/256/384/512 | 317 | Финальный архив авторов: `KAT_MCT/ShortMsgKAT_*.txt`, только длины, кратные 8 битам; дополнительно `LongMsgKAT_*.txt` до 4096 байтов включительно |
| JH-224/256/384/512 | 317 | Финальный архив от 16 января 2011 года; такие же ограничения ShortMsg/LongMsg |
| Ascon-Hash256 | 1025 | `crypto_hash/asconhash256/LWC_HASH_KAT_128_256.txt`, все сообщения от 0 до 1024 байтов |
| Ascon-XOF128-256 | 1025 | `crypto_hash/asconxof128/LWC_XOF_KAT_128_512.txt`, первые 32 байта опубликованного XOF-вывода |
| Ascon-CXOF128-256 | 33 | `crypto_cxof/asconcxof128/LWC_CXOF_KAT_128_512.txt`, только пустая строка `Z`, первые 32 байта вывода |
| Skein-256-256, Skein-1024-1024 | 34 | Skein 1.3 `skein_golden_kat.txt`: только последовательный режим без ключа, входная длина кратна 8 битам |
| Skein-512-256 | 259 | Тот же файл и NIST ShortMsgKAT для 256-битного результата с 512-битным состоянием; одинаковые входы удалены |
| Skein-512-512 | 289 | Тот же файл и NIST ShortMsgKAT для 512-битного результата; одинаковые входы удалены |
| BLAKE2b-256/512, BLAKE2s-256 | 268 | Python `hashlib.blake2b` / `blake2s`, параметр `digest_size` задаётся при создании состояния |
| Kupyna-256/384/512 | 269 | Независимая эталонная реализация автора `Roman-Oliynykov/Kupyna-reference` |
| Whirlpool | 140 | OpenSSL 3.5.5, `openssl dgst -provider legacy -whirlpool`; окончательная редакция 2003 года |
| TurboSHAKE128-256, TurboSHAKE256-512, KT256-512 | 4 + 4 больших | RFC 9861: пустое сообщение и сообщения длиной `17^i`, `i=0..6`; только домен `1F` для TurboSHAKE и пустая строка настройки для KT256 |

Для независимых BLAKE2/Kupyna/Whirlpool примеров байт с индексом `i` равен
`i % 251`. Длины BLAKE2: `0..259`, `511,512,513,1023,1024,1025,4095,4096`.
Длины Kupyna — те же и `2048`. Длины Whirlpool: `0..129`,
`255,256,257,511,512,513,1023,1024,1025,4096`.
В больших примерах RFC байты также равны `i % 251`.

Дополнительные 28 примеров с тем же заполнением получены через PyCryptodome
3.23.0 (`Crypto.Hash.TurboSHAKE128` / `TurboSHAKE256`). Для TurboSHAKE проверены
длины `rate-1`, `rate`, `rate+1`, `2*rate-1`, `2*rate`, `2*rate+1`, где rate
равен 168 или 136 байтам, домен — `1F`. Для KT256 использована отдельная
непотоковая реализация псевдокода приложения A.5 RFC 9861 поверх TurboSHAKE256;
она предварительно сверена со всеми опубликованными большими KT256-примерами.
Длины KT256: `8190..8193`, `16382..16385`, `24574..24577`, `2097151`,
`2097152`, `2105343`, `2105344`. Они охватывают включение древовидного режима,
дополнение последнего блока и переход счётчика листьев с 255 на 256.

## Различия, которые нельзя игнорировать

- Выход BLAKE2b-256 не равен усечению BLAKE2b-512.
- Ascon SP 800-232 отличается от предшествующих заявок Ascon; старые KAT
  нельзя использовать как эталоны окончательного стандарта.
- Древовидные и MAC-векторы Skein проверяют другие параметры. Они исключены
  из этого набора. В имени Skein первое число обозначает состояние, второе —
  выход; Skein-256-256 и Skein-512-256 дают разные результаты.
- KT256-512 использует 256-битный вариант KangarooTwelve. Прежний K12-512
  остаётся 128-битным вариантом с 512-битным выходом.
- Фиксированная длина XOF-вывода входит в контракт имени алгоритма. CXOF
  использует пустую строку настройки, включая предусмотренное стандартом
  кодирование её длины и дополнение.
- Whirlpool — окончательная редакция, а не Whirlpool-0 или Whirlpool-T.

Успех этих тестов проверяет реализацию на выбранных входах. Он не является
сертификацией NIST, доказательством криптостойкости или заменой испытаний
Windows x86/x64/ARM64, больших файлов, интерфейса и установки.
